# v2 개발 기록

무엇을 만들었고, 무엇이 왜 그렇게 됐는지에 대한 기록입니다. 쓰는 방법은
[README](../README.md) 에 있습니다. 이 문서는 **다시 겪지 않으려고 적어두는
것들** — 증상만 보고는 알 수 없었던 원인들과, 그걸 알아내는 데 왜 오래 걸렸는지 —
에 무게를 둡니다.

릴리스: `v2.0.0`. v1 은 `v1.0.0` 에서 동결됐습니다 ([docs/v1.md](v1.md)).

---

## 1. v1 을 버린 이유

v1 은 WebDAV 프록시였습니다. 플레이어가 보내는 요청만 보고 "지금 재생하려는
것인지"를 판단해 변환을 시작했습니다.

**그 판단이 불가능합니다.** 썸네일을 만들려고 파일을 여는 요청과 재생을 시작하는
요청이 **바이트 단위로 동일**합니다. 헤더도, 범위도, 순서도 같습니다. 둘을 가르는
규칙을 세울 때마다 한쪽이 깨졌고, 마지막에는 폴더를 열자마자 재생을 누르는 가장
평범한 사용에서 재생이 실패했습니다.

버그가 아니라 **전제가 틀린 것**이었습니다. v2 는 사용자가 웹에서 직접 고르므로
알아낼 것이 없습니다. 클릭이 곧 의도입니다.

v1 은 트리에 남아 있고 컴파일·테스트도 되지만 배포하지 않습니다. `ver2` 가 `ver1`
을 **컴파일 단계에서 import 할 수 없습니다**(`internal/` 규칙). 동결이 규율이 아니라
컴파일러로 보장됩니다.

## 2. 실측값 (Celeron J1900, 4GB)

추측으로 정할 뻔한 것들을 재서 정했습니다.

| | |
|---|---|
| 비디오 스트림 복사 | 215x |
| AC3 디코딩 | 71x |
| 디스크 | 191 MB/s |
| **x264 1080p 인코딩** | **0.717x** |
| AAC 인코딩 | 4x |
| MP3 | 6x |
| FLAC | 60x |

**x264 0.717x 가 제품 설계를 결정했습니다.** 29분 에피소드에 40분이 걸리고,
재생이 인코더를 따라잡으므로 **11분 30초를 벌어둔 뒤에야** 끝까지 볼 수 있습니다.
10% 검증 관문은 약 4분 뒤에 도달합니다.

v1 시절의 의외의 발견: 이 CPU 의 병목은 **오디오 인코더의 심리음향 모델**이었습니다
(AAC 4x 인데 FLAC 은 60x). 그래서 v1 은 컨테이너만 바꾸는 경로를 우선했습니다.

`NVT2_WORKERS` 를 1 로 두는 이유도 여기 있습니다. 늘리면 전체가 느려질 뿐입니다.

## 3. 겪은 문제와 원인

증상만으로는 알 수 없었던 것들입니다. 대부분 **원인이 상식적인 곳에 없었습니다.**

### 자막이 안 구워졌다 — 세 겹이었습니다

한 번 고칠 때마다 다음 층이 드러났습니다.

1. **목록의 버튼이 자막 선택 없이 변환을 시작했습니다.** 목록과 상세에 똑같이
   생긴 버튼이 있었는데, 목록에는 자막 선택기가 없어 `subs` 가 빈 값으로 갔습니다.
   → 변환 시작을 상세 한 곳으로 모았습니다.
2. **자막 파일이 한글로 인식되지 않았습니다.** 이 라이브러리에서 가장 흔한 모양이
   `데스노트 03 (704x396 DivX).smi` 처럼 **영상과 이름이 똑같고 언어 꼬리표가 없는**
   파일입니다. 자막이 하나뿐이니 구분할 표식을 붙일 이유가 없었던 것이고, `.ko.`
   같은 걸 찾는 규칙은 여기서 아무것도 못 찾습니다.
   → **파일을 열어 한글이 있는지 봅니다.** 앞부분 64KB 를 UTF-8 또는 CP949 로
   디코딩해 한글 음절을 찾습니다. 이름 규칙과 달리 영어 자막을 한글로 오인할 수
   없습니다.
3. **컨테이너에 폰트가 하나도 없었습니다.** `fc-list | wc -l` 이 `0`,
   `/usr/share/fonts` 자체가 없었습니다. 알파인 기본 이미지에는 폰트가 없습니다.

**세 번째가 제일 오래 걸렸습니다.** libass 는 글자를 그릴 폰트를 못 찾으면
**경고만 남기고 아무것도 안 그린 채 정상 종료합니다.** ffmpeg 도 0 으로 끝납니다.
한 시간 뒤에 자막 없는 파일이 나오는데 어디에도 오류가 없습니다. 자막 파일은
대사 320줄이 멀쩡히 들어 있었고, `-vf subtitles=` 도 명령줄에 있었고, 스타일의
위치(`Alignment 2`, `MarginV 10`)도 정상이었습니다.

→ `font-noto-cjk` 를 이미지에 넣었습니다. 그리고 **ffmpeg 의 경고를 성공했을 때도
로그에 남기게** 했습니다 — 그 한 줄이 있었으면 처음부터 알았을 것입니다.

관련해서 함정 하나 더 막았습니다: ffmpeg 은 SAMI 헤더만 읽고 대사를 하나도 못 찾아도
**정상 종료하면서 빈 ASS 를 만듭니다.** 그대로 구우면 성공적으로 아무것도 안 그린 채
한 시간이 지납니다. 이제 `Dialogue:` 줄이 없으면 그 자리에서 실패합니다.

### 변환 중 재생이 초 단위로 건너뛰었다 (1,2,3 → 8,9)

HLS 재생목록은 인코딩이 끝날 때까지 `#EXT-X-ENDLIST` 가 없습니다. **끝 표시가 없는
재생목록을 모든 플레이어가 생방송으로 읽고, 생방송은 가장 최신 세그먼트부터
시작합니다.** 그 세그먼트는 인코더가 방금 만든 지점이고 인코더는 0.717배속입니다.
플레이어가 꼬리에 붙어 몇 초마다 굶고, 기다리는 동안 도착한 곳으로 건너뜁니다.

→ 재생목록에 `#EXT-X-START:TIME-OFFSET=0` 을 넣습니다. hls.js 도 Safari 기본
재생기도 이걸 생방송 규칙보다 우선합니다. hls.js 에는 `startPosition: 0` 도
함께 걸었습니다.

같이 고친 것: 아직 인코더가 도달하지 않은 세그먼트의 404 가 `immutable` 로 나가고
있었습니다. 브라우저가 그 구멍을 1년간 기억합니다.

### 에어플레이로 재생이 안 됐다 — 진단 사다리로 좁혔습니다

원인을 짐작할 수 없어서 **같은 장면 60초를 네 가지로 인코딩**하는 기능을 임시로
만들었습니다. 아래로 갈수록 포기하는 것이 늘어나고, 재생되기 시작하는 칸이 곧
원인이라는 발상이었습니다 — High@4.2 원본 크기부터 Baseline@3.0 360p 까지.

**넷 다 실패했고 기존 `.mp4` 도 실패했습니다.** 마지막 칸은 십 년 된 기기도 받는
조합이라, 이 결과가 "원인은 인코딩이 아니다" 를 말해줬습니다. 사다리는 답을 맞히지
못했지만 **방향을 바꿀 근거**를 줬고, 그게 목적이었습니다.

원인이 밝혀진 뒤 이 기능은 제거했습니다. 한 번 쓰고 나면 남겨둘 이유가 없는
도구였고, 화면과 코드에 남아 다음 사람을 헷갈리게 할 뿐입니다. 같은 상황이 또
오면 다시 만드는 편이 낫습니다 — 그때 좁혀야 할 축은 또 다를 테니까요.

원인은 **basic auth** 였습니다. 에어플레이는 브라우저가 화면을 보내는 게 아니라
**사파리가 애플TV 에게 주소를 건네고 애플TV 가 파일을 직접 받아가는** 것입니다.
애플TV 는 브라우저의 로그인을 물려받지 않고, 비밀번호를 입력할 화면도 없습니다.
모든 요청이 401 이고 화면은 검은 채로 있습니다.

→ **미디어 링크에만 서명을 붙였습니다.** 로그인한 사람이 연 페이지가 만들어준
링크는 하루 동안 동작하고, 서명이 경로를 포함하므로 다른 파일에 옮겨 쓸 수 없습니다.
재생목록이 가리키는 세그먼트에도 같은 서명이 붙습니다 — 목차만 열어주고 내용을
막으면 의미가 없습니다. 나머지 전부(탐색, 변환 시작, 취소)는 비밀번호 뒤에
그대로입니다.

덤으로 알게 된 것: **인덱스가 파일 끝에 있어도 에어플레이는 됩니다.** `+faststart`
는 네트워크 재생 시작을 앞당기는 값이지 Apple TV 의 요구 조건이 아닙니다.

### 텔레그램 알림이 안 왔다 — 코드가 아니라 배포였습니다

로그의 `telegram: off` 한 줄이 답이었습니다. 토큰을 `.env` 로 옮기면서 compose 를
`${NVT2_TELEGRAM_TOKEN:-}` 로 바꿨는데, **`:-` 는 값이 없어도 경고 없이 빈
문자열로 채웁니다.** 그리고 나스의 Container Manager 프로젝트가 v1 폴더
(`/volume1/docker/nvt`)에서 돌고 있어서, `/volume1/docker/nvt2` 에 둔 `.env` 를
아무도 읽지 않았습니다.

→ `:-` 를 빼서 compose 가 경고하게 하고, 시작 로그가 값의 출처를 말하게 했습니다.

## 4. 진짜 교훈 — 대부분 관측 가능성 문제였습니다

위 문제들에서 **고치는 데 걸린 시간보다 원인을 보는 데 걸린 시간이 훨씬 길었습니다.**
같은 종류의 구멍이 다섯 군데 있었습니다.

| 구멍 | 결과 | 고친 것 |
|---|---|---|
| ffmpeg 경고를 **실패했을 때만** 보고 | 폰트 경고가 사라짐 | 성공해도 남김 |
| 인증이 로그보다 **바깥** | 401 이 로그에 안 찍힘 | 로그가 바깥 |
| 접근 로그에 상태·요청자 없음 | 사파리와 애플TV 구분 불가 | `-> 206 from … AppleCoreMedia/…` |
| 어느 빌드가 도는지 알 수 없음 | 고친 걸 배포 안 하고 "안 된다" 판단 **2회** | 시작 줄에 `build <sha>` |
| 어느 자막을 구웠는지 기록 없음 | 보고를 대조할 것이 없음 | 트랙 이름, 안 구웠으면 이유 |

특히 **"실패했을 때만 보고한다"** 는 패턴이 두 번 물렸습니다. ffmpeg 경고와 401
둘 다, **실패하지 않는 종류의 실패**였습니다. 정상 종료하면서 아무것도 안 하는
것이 가장 찾기 어렵습니다.

## 5. 설계 결정

**디렉터리는 `ver1`/`ver2`** — `v2` 는 Go 가 `모듈경로/v2` 를 메이저 버전 2인 별개
모듈로 해석하는 예약 패턴이라 쓸 수 없습니다.

**v1 코드를 재사용하지 않았습니다.** 공유 모듈을 만들면 v2 를 고칠 때마다 v1 을
재검증해야 해서 동결이 거짓말이 됩니다. 중복은 약 120줄이고 그게 더 쌉니다. v1 의
LRU 캐시 제거는 v2 에서는 **버그**입니다 — 사용자가 명시적으로 요청한 파일을 몰래
지우는 것이니까요.

**확장자가 아니라 코덱으로 판정합니다.** `.mkv` 안의 H.264+AAC 는 컨테이너만 바꾸면
몇 초인데 확장자 기준이면 40분입니다. 반대로 `.mp4` 안의 HEVC+AC3 는 변환된 것처럼
보이지만 재생되지 않습니다.

**`-f tee` 로 한 번만 인코딩합니다.** 출력을 두 개 쓰면 인코더가 두 번 돌아 이
하드웨어에서는 치명적입니다.

**미리보기는 배치의 첫 파일에만.** 목적이 10% 검증 관문이고 그 판단은 첫 편에서
끝납니다. HLS 지선이 붙으면 4초마다 키프레임을 강제해야 해서 같은 비트레이트에서
화질이 떨어지므로, 둘째 편부터는 낼 이유가 없는 비용입니다.

**경로 보안은 `outpath` 한 곳에서.** v2 는 사용자가 준 경로로 **파일을 씁니다** —
읽기 전용이던 v1 에 없던 위험입니다. 검증된 경로만 담는 타입 `Rel` 의 생성자를
`ParseRel` 하나로 제한해, 검증 안 된 문자열이 타입 검사에서 막히게 했습니다.
`os.OpenRoot`(Go 1.24)로 심볼릭 링크 탈출까지 차단합니다.

v1 의 버그 하나는 물려받지 않았습니다 — `strings.Contains(path, "..")` 는
`Foo..Bar.mkv` 라는 **정상 파일명을 거부**합니다. 경로 요소 단위로 검사합니다.

**변환 시작은 상세 페이지 한 곳에서만.** 같아 보이는 버튼이 다르게 동작하는 것이
자막 사고의 원인이었습니다.

**자막 기본값은 한글 있으면 그것, 없으면 굽지 않음.** 빠진 자막은 다시 변환하면
되지만 원하지 않은 언어가 박히면 되돌릴 수 없고, 알아차리는 비용이 재인코딩
한 번입니다.

## 6. 확인된 것 / 아직 모르는 것

**확인됨** — 실물로 돌려봤습니다.

- `.smi` → `.ass` → 굽기. CP949 SAMI(한글·영어 두 클래스, 대사 320줄)로 끝까지.
- 에어플레이 + 서명된 링크. Apple TV 4K(2023), basic auth 켠 채로.
- 인덱스가 파일 끝에 있어도 에어플레이는 됩니다.
- 재시작 후 큐 이어받기. 변환 중이던 파일은 처음부터 다시 합니다 — 중단된 MP4 는
  인덱스가 없어 이어붙일 방법이 없습니다.

**모름**

- **HEVC 파일이 Infuse 에서 재생되지 않던 원인.** Apple TV 4K 는 HEVC Main10 을
  하드웨어로 디코딩하고 오디오도 AAC 였는데 재생되지 않았습니다. v2 는 H.264 로
  재인코딩해 우회하지만 원인은 여전히 모릅니다. **v2 를 만든 계기가 이것인데
  끝내 설명하지 못했습니다.**
- `-f tee` + `movflags=+faststart` 조합. 실시간 경로에서는 빼두었습니다. 에어플레이가
  이것과 무관한 게 확인됐으니 급하지 않고, 남은 이점은 네트워크 재생 시작이
  빨라지는 것뿐입니다.

## 7. 배포 환경 메모 (Synology)

- **바인드 마운트 경로를 미리 만들어야 합니다.** Synology 의 도커는 없는 경로를
  자동 생성하지 않고 `Bind mount failed` 로 컨테이너가 뜨지 않습니다.
- **`.env` 는 compose 의 작업 디렉터리에 있어야 합니다.** 어디인지는
  `docker inspect nvt2 --format '{{index .Config.Labels "com.docker.compose.project.working_dir"}}'`
  가 말해줍니다. Container Manager 로 만든 프로젝트는 폴더 이름과 다를 수 있습니다.
- **컨테이너 안 클라이언트 주소는 전부 도커 브리지 게이트웨이**(`172.23.0.1` 등)
  입니다. 접근 로그의 IP 는 쓸모가 없고 User-Agent 만 유효합니다.
- **HTTPS 는 열린 문제입니다.** 이 회선은 ISP 가 80·443 인바운드를 막아 ACME 의
  HTTP-01 도 TLS-ALPN-01 도 쓸 수 없습니다. 실질적인 선택지는 DNS-01(도메인과 DNS
  API 필요)이거나 VPN 입니다. VPN 쪽이 이 도구에는 더 맞습니다 — 에어플레이는 집
  안에서 일어나는 일이고, 밖에서 필요한 건 알림 링크를 눌러 확인하는 정도입니다.
