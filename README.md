# nas-video-transcoding

NAS 에 있는 동영상을 골라서 MP4 로 변환하는 웹 도구입니다. 브라우저에서 폴더를
열고, 볼 파일을 고르고, 변환되는 동안 지켜보다가, 끝나면 그 자리에서 재생합니다.

| | 방식 | 상태 |
|---|---|---|
| **[v1](docs/v1.md)** | WebDAV 프록시. 플레이어의 요청을 보고 재생 의도를 추측 | 동결 (`v1.0.0`) |
| **v2** | 웹 UI. 사용자가 직접 고르고, 추측하지 않음 | 현재 |

## 왜 v2 인가

v1 은 플레이어가 보내는 요청만으로 "지금 재생하려는 것인지"를 알아내야 했습니다.
그게 되지 않습니다 — 썸네일을 만들려고 파일을 여는 요청과 재생을 시작하는 요청이
**바이트 단위로 동일**합니다. 둘을 가르는 규칙을 세울 때마다 한쪽이 깨졌고,
마지막에는 폴더를 열자마자 재생을 누르는 정상적인 사용에서 재생이 실패했습니다.

v2 는 클릭이 곧 의도이므로 알아낼 것이 없습니다.

## 무엇을 하는가

**탐색하고 고릅니다.** 폴더를 열면 원본 라이브러리가 그대로 보입니다. 파일을 누르면
상세 화면이 열리고, **거기 한 곳에서만** 변환이 시작됩니다 — 안에 무슨 코덱이 들었는지
보고, 자막을 고르고, 범위를 **이 파일만 / 여기서부터 끝까지 / 폴더 전체** 중에서
정합니다. 목록에도 같은 버튼을 두었다가 뺐습니다. 목록에는 자막 선택기가 없어
똑같이 생긴 버튼이 조용히 자막 없는 변환을 시작했고, 그건 버그로만 보입니다.

**순서가 곧 제품입니다.** 어느 버튼이든 **고른 파일이 큐의 맨 앞**입니다. 오늘 볼 것이
가장 먼저 준비됩니다. "폴더 전체"는 고른 지점을 축으로 회전해 앞쪽 편을 마지막에
돌립니다. 정렬은 자연 정렬이라 10화가 2화보다 앞에 오지 않습니다.

**변환하면서 볼 수 있습니다.** MP4 는 완성 전에 재생할 수 없어서(인덱스가 파일 끝에
쓰입니다) HLS 를 함께 만듭니다. 인코딩은 한 번만 돌고, 이미 만들어진 구간 안에서는
되감기도 됩니다.

재생은 **항상 처음부터** 시작합니다. 끝나지 않은 재생목록에는 종료 표시가 없고,
종료 표시가 없는 재생목록을 플레이어는 생방송으로 읽어 **가장 최신 세그먼트에
붙습니다**. 그 자리는 인코더가 방금 만든 지점이라 몇 초마다 재생할 것이 떨어지고,
기다렸다가 그동안 도착한 곳으로 건너뜁니다 — 화면에서는 1,2,3 다음에 8,9 로
보입니다. 재생목록에 `#EXT-X-START` 를 넣어 처음을 가리키게 합니다.

**자막을 구울 수 있습니다.** 내장 트랙과 옆에 놓인 자막 파일을 모두 찾아 **한글을
먼저** 보여줍니다.

**첫 파일이 10% 를 지나면 텔레그램으로 알립니다.** 인트로가 지난 지점이라 자막이
화면에 나오고, 싱크를 눈으로 확인할 수 있습니다. 아니다 싶으면 **거기서 나머지를
중단**합니다.

**원본은 건드리지 않습니다.** 출력은 원본 트리를 미러링한 별도 폴더로 갑니다.

**껐다 켜도 큐가 남습니다.** 남은 파일 목록이 디스크에 기록돼 있어 재시작하면
이어서 진행합니다. 다만 **변환 중이던 파일은 처음부터 다시** 합니다 — 중단된
MP4 는 인덱스가 없어 이어붙일 방법이 없기 때문입니다. 그 파일은 큐 맨 앞에
있었으니 다시 맨 앞에서 시작합니다.

## 실행

```bash
sudo mkdir -p /volume1/downloads/_nvt /volume1/docker/nvt2/state
mkdir -p /volume1/docker/nvt2 && cd /volume1/docker/nvt2
curl -sO https://raw.githubusercontent.com/kang3q/nas-video-transcoding/main/docker-compose.nas.yml
mv docker-compose.nas.yml docker-compose.yml
vi docker-compose.yml          # 볼륨 경로 확인
sudo docker compose up -d
```

브라우저에서 `http://<나스IP>:8081`.

> Synology 의 Docker 는 바인드 마운트 경로를 자동으로 만들지 않습니다. 위의
> `mkdir -p` 를 먼저 하지 않으면 `Bind mount failed` 로 컨테이너가 뜨지 않습니다.

v1 을 계속 쓰신다면 `docker-compose.v1.nas.yml` 이 `v1.0.0` 에 고정돼 있어 나란히
돌릴 수 있습니다 (v1 은 8080, v2 는 8081).

## 변환 규칙

확장자가 아니라 **실제 코덱**을 보고 정합니다.

| 상황 | 처리 | 속도 |
|---|---|---|
| 이미 H.264 + AAC | 컨테이너만 교체 | 수 초 |
| 그 외 | H.264 + AAC 로 재인코딩 | J1900 에서 0.717x |

`.mkv` 안의 H.264+AAC 를 확장자만 보고 재인코딩하면 40분이 걸리지만 코덱을 보면
몇 초입니다. 반대로 `.mp4` 안의 HEVC+AC3 는 변환된 것처럼 보이지만 재생되지
않습니다.

실측값(Celeron J1900, 29분 에피소드):

| | |
|---|---|
| 인코딩 완료 | 약 40분 |
| 끊김 없이 처음부터 볼 수 있게 되는 시점 | 약 11분 30초 후 |
| 10% 검증 관문 도달 | 약 4분 후 |

출력은 Apple TV 4K 를 기준으로 맞춰져 있습니다 — `+faststart`, 1080p 이하,
`-profile:v high -level 4.2`. 근거는 [docs/appletv-compatibility.md](docs/appletv-compatibility.md).

## 자막

찾은 트랙을 라디오 버튼으로 **전부 펼쳐** 보여줍니다. 굽기는 되돌릴 수 없으니
무엇이 화면에 박힐 참인지 목록을 열어보지 않고도 읽혀야 합니다. 그림
자막(`dvd_subtitle` 등)은 굽을 수 없으므로 고를 수 없게 표시합니다.

기본값은 **한글 자막이 있으면 그것, 없으면 굽지 않음**입니다. 빠진 자막은 다시
변환하면 되지만 원하지 않은 언어가 박히면 되돌릴 방법이 없고, 그걸 알아차리는
비용이 재인코딩 한 번입니다. 그래서 영어만 있는 파일은 꺼둔 채로 둡니다.

여러 편을 한 번에 변환하면 파일마다 고를 수 없으므로, **고른 트랙의 언어를 나머지
편에도 적용**합니다. 그 언어가 없는 편은 **자막 없이** 변환됩니다 — 빠진 자막은 다시
변환하면 되지만, 원하지 않은 언어가 화면에 박히면 되돌릴 수 없습니다.

한국어 `.smi` 는 대부분 CP949 라, ffmpeg 에 넘기기 전에 UTF-8 로 바꿉니다.

## 설정

| 변수 | 기본값 | 의미 |
|---|---|---|
| `NVT2_SOURCE_DIR` | `/media` | 원본 라이브러리, 읽기 전용 |
| `NVT2_OUTPUT_DIR` | `/output` | 변환 결과물 |
| `NVT2_STATE_DIR` | `/state` | 캐시와 임시 파일 |
| `NVT2_LISTEN` | `:8080` | 리슨 주소 |
| `NVT2_USER` / `NVT2_PASS` | — | 선택적 basic auth |
| `NVT2_WORKERS` | `1` | 동시 변환 수 |
| `NVT2_THREADS` | `3` | ffmpeg `-threads` |
| `NVT2_PRESET` | `superfast` | x264 프리셋 |
| `NVT2_VIDEO_BITRATE` | `2600k` | |
| `NVT2_AUDIO_BITRATE` | `320k` | |
| `NVT2_LIVE` | `true` | 변환 중 시청용 HLS 생성 |
| `NVT2_SEGMENT_SEC` | `4` | HLS 세그먼트 길이 |
| `NVT2_CHECKPOINT_PERCENT` | `10` | 첫 파일 확인 시점 |
| `NVT2_TELEGRAM_TOKEN` | — | 없으면 알림 비활성. **`.env` 에 적습니다** |
| `NVT2_TELEGRAM_CHAT_ID` | — | 같음 |
| `NVT2_PUBLIC_URL` | — | 알림에 넣을 웹 주소. 같음 |

토큰 같은 값은 compose 파일이 아니라 그 옆의 `.env` 에 둡니다. `.env` 는
커밋되지 않으므로 실수로 저장소에 들어갈 일이 없습니다.

```bash
cp .env.example .env && vi .env
```

출력 폴더는 원본 폴더 안에 두어도 됩니다 — 탐색 목록에서 자동으로 숨겨집니다.

## 구조

```
ver1/    동결. 컴파일·테스트는 되지만 배포하지 않습니다
ver2/
  internal/outpath/    경로 매퍼이자 경로 보안의 유일한 창구
  internal/library/    원본 탐색과 큐 순서 (자연 정렬, 회전)
  internal/mediainfo/  ffprobe. 코덱·길이·트랙 목록
  internal/subs/       자막 탐색·CP949 변환·선택
  internal/ffmpeg/     argv 조립, 실행, 진행률 파싱
  internal/jobs/       배치·큐·진행률·취소·검증 관문
  internal/notify/     텔레그램 (알림 + 중단 버튼)
  internal/web/        핸들러와 go:embed 된 화면
docs/                  v1 문서, Apple TV 호환성 기준
```

`ver2` 는 `ver1` 의 코드를 **컴파일 단계에서 import 할 수 없습니다** (`internal/`
규칙). 동결이 규율이 아니라 컴파일러로 보장됩니다.

디렉터리 이름이 `v1`/`v2` 가 아닌 이유는 Go 가 `모듈경로/v2` 를 메이저 버전 2인
별개 모듈로 해석하는 예약 패턴이기 때문입니다.

## 개발

```bash
go build ./... && go test ./...
go run ./ver2/cmd/nvtweb        # NVT2_SOURCE_DIR 등을 지정해서
```

의존성은 두 개뿐입니다 — `x/net`(v1 의 WebDAV), `x/text`(CP949 디코딩).
화면은 `html/template` + `go:embed` 라 빌드 단계도 CDN 도 없습니다. hls.js 는
버전과 체크섬을 기록해 벤더링했습니다 (NAS 가 오프라인일 수 있습니다).

## 아직 확인되지 않은 것

- **HEVC 파일이 Infuse 에서 재생되지 않던 원인.** Apple TV 4K 는 HEVC Main10 을
  하드웨어로 디코딩하고 오디오도 AAC 였는데 재생되지 않았습니다. v2 는 H.264 로
  재인코딩해 우회하지만, 원인은 여전히 모릅니다.
- **`.smi` → `.ass` 변환.** ffmpeg 의 SAMI 디먹서에 의존하는데, 실제 `.smi` 는
  HTML 이 깨진 경우가 많습니다.
- **`-f tee` + `movflags=+faststart`.** 실시간 출력 경로에서는 faststart 를 빼
  두었습니다. tee 가 슬레이브에 탐색 가능한 출력을 주는지 확인되지 않았고, 실패하면
  결과물을 잃습니다.
